# 위시 RP Manager — 0.17.15.4(키메라 버전)

Crack의 장기 RP에서 현재상태, 날짜로그, 중요물품, 인물정보, 타임라인, 자료집, 기타·OOC를 관리하는 사용자 스크립트입니다. 원작 위시 RP Manager를 바탕으로 개선했으며, 현재 배포판은 임시57의 기능을 이어받은 **키메라 버전**입니다. 원작 0.17.15와 구분해서 사용하세요.

## 이번 업데이트: 0.17.15.4

- 백업을 가져오기 전에 방 기억과 설정집 내용을 확인할 수 있습니다.
- 현재 RP와 연결되지 않는 방 ID·기준점·원문 상태를 읽고 승인하면 백업을 가져올 수 있습니다. 원문 조회를 생략하고 미확인 상태로 진행할 수도 있습니다.
- 가져온 뒤 미해결 항목과 후속 조치를 안내합니다. 기억의 누락·중복·현재 RP와 다른 내용이 발견되면 원문을 확보한 뒤 **전체 기억 재구축**을 시행해 보시길 권장합니다. 재구축은 가져오기 필수 조건이 아닙니다.
- 백업 선택·승인·복사 중 방이 바뀌면 추가 저장을 중단합니다. 다른 방에 복사한 뒤에는 자동 기억정리 시작점을 확인합니다.

## 설치

1. Chrome 등 지원 브라우저에 **Tampermonkey**를 설치합니다.
2. **[현재 키메라 버전 설치](https://raw.githubusercontent.com/dinggadingga0515/wish-rp-manager-improved/main/%EC%9C%84%EC%8B%9C_RP_Manager_%EA%B0%9C%EC%84%A0.user.js)** 링크를 열고 Tampermonkey 설치 화면에서 설치합니다.
3. 원작 또는 다른 임시 버전 매니저는 꺼 두고, 사용할 Crack RP 방을 새로고침한 뒤 매니저를 엽니다.

루트의 [`위시_RP_Manager_개선.user.js`](./위시_RP_Manager_개선.user.js)가 현재 설치 파일입니다. 자동 업데이트도 이 저장소의 같은 파일을 사용합니다.

## 처음 시작하기

매니저의 첫 **확인** 화면에서 **처음 시작·자료 이사 → 시작 방법 선택**을 누르세요. **자료 관리 → 도구·복사·백업·복원**에서도 같은 기능을 열 수 있습니다.

### 원작 .14/.15 등에서 백업을 가져오는 경우

1. 기존 매니저에서 **전체 백업 JSON**을 받아 보관합니다.
2. 키메라 버전에서 **백업 JSON으로 이사**를 눌러 파일을 선택합니다.
3. **백업 내용 보기 / 설정집 내용 보기**로 자료를 확인하고, 가져올 방과 설정집을 선택합니다.
4. 다른 매니저 탭을 닫고 확인란을 체크합니다. 같은 RP에 복원할 때는 **원래 방에 복원**, 삭제된 원래 방의 기억을 지금 열어 둔 RP로 옮길 때는 메인 백업 불러오기 화면의 **현재 방에 복사**를 사용합니다. 복사는 RP를 정확히 하나 선택하고 현재 방의 주입을 해제해야 합니다.
5. 표시된 현재 상태를 읽고 **미해결 상태를 이해하고 가져오기** 또는 **확인한 백업 가져오기**를 누릅니다. 조회를 기다리지 않으려면 **원문 확인 생략**을 누른 뒤 미확인 상태를 읽고 승인할 수 있습니다. 적용 전 자료의 퇴피 백업을 준비합니다.
6. 완료 안내와 자료 관리의 **백업 이사 당시 확인 기록**에서 남은 확인 사항을 살펴봅니다.

파일에 포함된 방 자료·방별 옵션·설정집을 복원합니다. 같은 ID의 내용을 복원하며 과거 자료와 임의로 합치지 않습니다. 원작 .14/.15 전체 백업에는 별도 전역 설정이 없으므로, 파일에 없는 전역 설정은 현재 값으로 유지됩니다. API 인증키는 백업으로 옮기지 않습니다.

과거 주입 복구 기록은 비활성으로 보존합니다. 복원 후 필요한 방에서 서버 원문과 비교해 주입을 다시 준비하세요. 다른 방으로 복사한 경우 원래 자동 처리 근거도 비활성 복구 기록으로 보관하고 새 방의 시작점을 지정합니다.

원래 방이 삭제되어도 백업 기억을 저장할 수 있습니다. **원래 방에 복원**하면 원래 방 ID로 보관되므로, 현재 방에서 사용하려면 **현재 방에 복사**를 선택하세요. 원작 백업에 전체 턴 수가 없으면 ‘백업 당시 전체 턴 수는 미기록’으로 표시합니다. 긴 RP는 최근 일부만 조회될 수 있으며, 이때 조회한 수를 전체 턴 수로 단정하지 않습니다. 기준점 연결이 미해결이면 일부 자동 기억정리가 보류될 수 있지만, 가져온 기억의 열람·편집과는 구분합니다.

### 백업 없이 처음 사용하는 경우

1. 해당 RP 방에서 **백업 없이 처음 시작 → RP 로그·지침 받기**를 누릅니다.
2. 받은 `Wish-전체재구축-TXT.zip`을 풀고, 모든 TXT를 번호순으로 같은 외부 AI 대화에 전달합니다.
3. 포함된 지침대로 마지막 파일까지 처리한 `Wish-RP-Manager-전체재구축.json`을 받습니다.
4. 준비한 방에서 **최종 JSON 가져오기 → 형식 검증·Diff**를 실행한 뒤, 반영할 영역을 선택합니다.

외부 AI를 직접 사용하는 이 경로에는 매니저용 API 키가 필요하지 않습니다. 외부 AI 서비스의 사용량·요금은 해당 서비스에 따릅니다. 결과가 올 때까지 현재 방의 준비 기록을 유지하세요. 파일 선택과 미리보기만으로는 기억을 저장하지 않습니다.

## 주요 기능

- 현재상태·날짜로그·물품·인물·타임라인·자료집·기타/OOC 관리와 컨텍스트 주입
- 수동 업데이트, AI 기억정리와 초안 검토·선택 반영
- 응답 교정과 선택한 변경의 적용 검증
- 사이트 저장소의 원본과 확장 저장소의 설정·복구 사본을 한 파일로 받는 전체 백업 JSON
- 백업 파일 시험 복원·재읽기, 저장 상태 진단, 저장량 보기와 선택 복구
- 전역 UTF-8 / UTF-16LE 요청 인코딩 선택

## 백업과 API 인증키

**전체 백업 JSON**은 현재 저장소의 원본·설정·복구 사본을 함께 보관합니다. 내용이 다른 과거 사본은 별도 복구 자료로 보존하며 자동으로 합치지 않습니다. **백업 파일 확인**은 시험 DB에 복원하고 다시 읽는 검사로, 현재 자료를 덮어쓰지 않습니다.

API 인증키는 브라우저에 저장할 수 있지만 **백업에서는 제외**됩니다. 다른 기기나 브라우저로 옮길 때는 따로 입력하세요. 사이트 데이터·브라우저 프로필이 삭제될 수 있으므로 전체 백업은 기기 밖에도 보관하세요. Tampermonkey 자체 백업만으로 사이트 IndexedDB까지 보관됐다고 간주하지 마세요.

## 검증 범위

최종 0.17.15.4에서 기준점 검사 35건, 가져오기 승인·취소·방 이동·삭제된 방 복사 검사 34건, 원작 .15 내보내기 5건과 새 설치로의 이사 검사 42건이 통과했습니다. 기존 수정창 32건, 화면·예약 11건, 백업·인증키 59건, 전체 프로그램 78건도 통과했습니다. 검사에는 서로 겹치는 범위가 있습니다.

전체 프로그램 검사 중 저장본 전체 비교가 한 차례 실패했고, 차이 기록을 추가한 이후 네 차례는 모두 통과했습니다. 최초 실패 원인은 미확정이며, 재실행 통과만으로 원인이 해결됐다고 단정하지 않습니다. 제보자의 실제 JSON과 이번 .4의 Tampermonkey 실사용은 아직 검증하지 않았습니다.

검사는 격리된 Chrome의 실제 DOM·IndexedDB와 합성 RP·GM·API 환경에서 수행했습니다. 실제 사용자 프로필이나 유료 AI 모델의 전수 검증을 의미하지 않습니다. 외부 AI가 작성한 기억의 사실관계는 Diff에서 직접 확인하세요.
